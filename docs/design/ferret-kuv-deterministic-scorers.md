# ferret-kuv — deterministic scorers: shared design

status: **proposed** (awaiting dk approval)
date: 2026-06-17
scope: resolves the load-bearing decisions shared across ferret-bbp, ferret-2p6, ferret-kuv.5, ferret-kuv.8, ferret-kuv.9, ferret-kuv.10.

## Why this doc exists

Enrichment of the 7 ready kuv-family beads found that all 7 are `requires_plan` and
that they keep colliding on the **same three architectural decisions**. Planned in
isolation, each leaf would re-decide them and diverge. This doc settles the three
once so the leaf plans/impls build coherently. It does **not** design any single
scorer — that stays leaf work.

Engine/analyst split is the invariant behind every call here: **ferret-side code is
deterministic and LLM-free; semantic judgement is the analyst's** (the kuv.2/kuv.4
precedent, README "AX-first").

---

## Decision 1 — User-turn text source

**Problem.** Two beads need the words the *human* typed adjacent to a tool stream —
bbp (repair/acceptance tagging) and kuv.9 (re-prompt friction). Today ferret throws
that text away. The two enrichers reached opposite instincts: bbp said "read from the
spine/raw path," kuv.9 said "capture it in the event model." Pick one.

**Ground truth.**
- `internal/event/event.go:9-30` — `Event` is payload-agnostic: 19 metadata fields,
  **no text field**. Kinds: `KindTool | KindShell | KindPrompt`.
- `internal/event/build.go:150-174` — `userLine()` emits a `KindPrompt` event from a
  text block it has *in hand* (`blk.Text`) but stores none of it.
- `cmd/ferret/spine.go:148-159` — `emitText()` separately re-reads the raw transcript
  and prints `[user] <text>` capped at `spineTextCap` (4000 runes). A second ingest
  path over the same bytes.

**Decision: capture prompt text once, in the Event artifact.**
Add one optional field to `Event`:

```go
Text string `json:"text,omitempty"` // populated only for KindPrompt; capped at promptTextCap
```

- Populate in `userLine()` (build.go:165) where `blk.Text` is already in scope; cap at
  a shared `promptTextCap` (reuse the 4000-rune `spineTextCap` constant).
- `omitempty` keeps tool/shell events byte-identical in the JSONL — only prompt rows grow.
- The artifact is regenerated by `ferret ingest`; a schema add is cheap, no migration.

**Consequences.**
- bbp and kuv.9 read user text uniformly from the tokenized artifact — neither re-reads
  raw transcripts, preserving "tokenization is the product" (README Design).
- `spine.go:emitText` can later source from `Event.Text` to collapse the two ingest
  paths. Not required by this epic; note it as cleanup.
- Rejected: `Detail` reuse (160-char cap loses re-prompt phrasing); sidecar join file
  (adds join logic to every miner); a separate raw-transcript pass per scorer (defeats
  the artifact).

## Decision 2 — Where deterministic scorers live

**Problem.** Five net-new deterministic scorers (gates ω, re-prompt, landmark, quality
axes, terminal-action) need a home. Every enricher independently warned "don't fold
into `conform`" yet several are "conformance-shaped." `mine` vs `conform` is the wrong
axis.

**Ground truth.**
- `internal/conform/conform.go:1-26` — header scopes it precisely: *replay observed
  calls against a **reference plan**, score fitness/precision*. `Align(reference,
  observed) Result`. It **requires an analyst-supplied reference**.
- `internal/mine/` — corpus-level heuristic discovery (n-grams, PrefixSpan, surprise,
  rank→Findings). `rank.go` shows mine already does deterministic multi-dimensional
  scoring, but over the **whole corpus**, not per task.
- The per-task unit is kuv.2's `segResult` scaffold in `cmd/ferret/segment.go` — logic
  currently sitting in `cmd/`, which is the wrong layer for reuse.

**Decision: a new package `internal/score/` for reference-free / self-reference
per-task scorers.** Three-way split by *reference source*, not by shape:

| Package | Reference source | Owns |
|---|---|---|
| `internal/conform` | external analyst reference plan | replay fitness/precision (kuv.4) — **unchanged** |
| `internal/mine` | none; cross-corpus frequency | n-grams, surprise, rank, Findings — **unchanged** |
| `internal/score` *(new)* | self / none, per task | gates ω, re-prompt, landmark, quality axes, terminal-action |

- The five new scorers are reference-free or score against the agent's *own* stated
  plan/landmarks (read from `Event.Text`, Decision 1) — they are neither analyst-replay
  nor corpus-frequency. They are a third category; give it a package.
- Per-task scorers operate on the `segResult` unit. Move the reusable scoring logic out
  of `cmd/ferret/segment.go` into `internal/score/`; `cmd/` stays a thin dispatch shell.
- Cross-session signals (re-prompt rate across sessions) may still read `mine.Corpus`,
  but the scorer code lives in `score/`.
- `conform/` is **frozen** for this epic: do not extend `Align`/`Result` with ω,
  landmark, or quality fields (the explicit ask of the 2p6 and kuv.10 enrichers).

**Rejected.** Bloating `mine/` with per-task logic (it's corpus-shaped); folding into
`conform/` (forces a fake "reference" where there is none); leaving logic in `cmd/`
(unreusable, untestable in isolation).

## Decision 3 — Extend the Finding model, or not

**Problem.** Do the new signals surface as `Finding`s? Adding a field ripples to three
sites; adding a `Kind` ripples further.

**Ground truth.**
- `internal/mine/finding.go:14-25` — `Finding` is **motif-centric**: `IDs` are motif
  token ids, `Count`/`Sessions` aggregate a *recurring pattern* across the corpus.
  Kinds: routine | friction | loop | noise.
- Two projections of the one model: `jf` (JSON, `cmd/ferret/main.go:1039-1077`) and
  `MDFinding` (markdown, `internal/out/md.go:16-25`). A new Finding field touches all
  three; a new Kind also touches `bucketKind()` (finding.go:50-61) and `mdSections`
  (md.go:46-51). Precedent: `Surprise` rides `jf` with `omitempty` and is simply absent
  from `MDFinding`.

**Decision: Finding stays the motif-discovery model. Per-task scores ride the segment
unit, not Finding.**

- **Per-task scores & outcome labels** (quality axes kuv.5, terminal-action kuv.8,
  landmark kuv.10, repair/acceptance bbp) → fields on the `segResult`/task model in
  `internal/score`, rendered by the segment/score output path. They are not motifs and
  must not be forced into `Finding`.
- **Genuine recurring motifs** (re-prompt-friction kuv.9, if it surfaces as a recurring
  pattern) → reuse the existing `Kind=friction`; do **not** add a new Kind. If a numeric
  score must ride along, add **one** optional `omitempty` field to `Finding` + `jf` and
  leave `MDFinding` untouched (the `Surprise` precedent). No new Kind, no `bucketKind`
  or `mdSections` churn.

**Rejected.** New Finding kinds per signal (renderer churn, dilutes the four-bucket
action map); overloading `Finding.Count` to mean per-task occurrence (breaks corpus
semantics).

## What each leaf does once this lands

| Bead | Builds on | Home |
|---|---|---|
| ferret-bbp | `Event.Text` (D1) | `internal/score` — repair/acceptance label on the task unit |
| ferret-2p6 | gate extraction + ω | `internal/score`, **not** `conform` |
| ferret-kuv.5 | quality axes, extends `mine/surprise` predictability | `internal/score`, per-task |
| ferret-kuv.8 | terminal-action label | `internal/score`, per-task outcome |
| ferret-kuv.9 | `Event.Text` (D1); re-prompt friction | `internal/score`; surface as `Kind=friction` Finding (D3) |
| ferret-kuv.10 | landmark/milestone match | `internal/score`, self-reference (not `conform`) |

ferret-kuv.6 is **not** in scope — it's the conformance-validation sign-off bead
(hand-run already passed per memory `ferret-conformance-validated-2026-06-17`); it needs
a `bd close`, not a plan.
